# Draft — VULN-1238 (release approval required)

- **Security:** Verify sealed-session access tokens using RS256 and the configured client's WorkOS JWKS. Reject invalid signatures, missing expiration/subject, mismatched cookie user IDs, and cookie impersonation without matching signed claims. Cache keys per client for ten minutes and retry discovery once for an unknown key ID.
- **Breaking:** `SessionManager::authenticate()` and `logout_url()` are now async. `helpers::session::authenticate_session` now requires `&Client` as its first argument and must be awaited. Authentication requires a configured client ID; managers without a client fail closed. There is no unverified fallback.
- **Migration:** Replace `manager.authenticate()` with `manager.authenticate().await`, `manager.logout_url(return_to)` with `manager.logout_url(return_to).await`, and `authenticate_session(cookie, password)` with `authenticate_session(&client, cookie, password).await`. Configure `Client::builder().client_id(...)` and permit access to the configured API base URL's `/sso/jwks/{client_id}` endpoint.

Current crate version: **3.4.0**. This is a stable-version public API break, not a pre-1.0 change. Implementation approval is not release approval: human maintainers must approve the breaking-release strategy/version before shipping; no version bump is made here. See `docs/security/VULN-1238.md` for the draft advisory and residual limitations.
